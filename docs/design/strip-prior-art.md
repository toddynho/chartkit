# Strip plot prior art

Survey for a ChartKit `strip` type. Vocabulary only. No code was copied. The reference use is the token benchmark: five libraries, nine models, one dot per model, a median tick, a min-to-max band, the ChartKit row emphasised, and a note between two medians.

## What v1 should take

Take the vocabulary people already say: a **group**, a **numeric position**, optional **jitter**, a **median or mean tick**, a **min–max or IQR band**, and a **highlighted group**. Default to the editorial horizontal row (Datawrapper, Flourish, Cleveland), because that is the benchmark chart. Draw the summary as a tick (Vega-Lite / Observable `tick`) and the band as a short range (Highcharts boxplot and Datawrapper range plot are the comparison, not the implementation). Color dots from the series palette. Use the accent token for a highlighted group and the muted token for the rest. The summary tick stays ink.

Leave these out of v1:

- Beeswarm (`swarmplot`, `Plot.dodgeY`). It needs a packing pass and is the wrong follow-up for a chart whose points usually do not collide.
- Random jitter without a stable offset. ggplot and seaborn re-roll. A ChartKit render has to be identical on the server and in every adapter, so an offset is a function of the row, not of `Math.random`. A seed option can wait.
- Confidence intervals (`pointplot`, boxplot whiskers at 1.5 IQR). The band is min–max or IQR only.
- A second chart type for the one-point case. That is a strip with the summary and the band hidden, which is the Cleveland dot plot.
- New color tokens, point-shape galleries, and a jitter option on `scatter`. Jitter for scatter is a follow-up if the strip offset proves useful.
