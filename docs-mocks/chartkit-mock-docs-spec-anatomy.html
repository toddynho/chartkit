Spec anatomy

A ChartKit chart is one JSON object — schema https://chartkit.dev/schema/v1.json. Required: version, type, a11y. Most charts also need data + encoding. Everything else (mark, axes, theme, …) has defaults. Same object in React, Vue, Svelte, vanilla, Markdown, and Node SVG.

Schema v1.json Required version · type · a11y Types 14 core Export ChartSpec

Minimal spec

Smallest drawable line. version is the string "1". type picks the chart. data is a row array (not { "values": [...] }). encoding.x / encoding.y name fields. a11y.alt is one sentence (10–500 chars) — required on every chart.

json · minimal 
{
  "version": "1",
  "type": "line",
  "data": [
    { "week": "W1", "signups": 18 },
    { "week": "W2", "signups": 28 },
    { "week": "W3", "signups": 42 },
    { "week": "W4", "signups": 56 }
  ],
  "encoding": { "x": "week", "y": "signups" },
  "a11y": { "alt": "Weekly signups rose from 18 to 56." }
}

Required & by-type

  • Always — version, type, a11y.alt.
  • Series charts (line, bar, donut, stacked-area, scatter, combo, heatmap, sparkline, mini-area, spike, candlestick) — data. Line/bar/donut/stacked-area/combo also require encoding.x + encoding.y. Scatter needs x+y. Heatmap needs x+color.
  • Metric charts (gauge, kpi, progress-ring) — metric.value (not top-level value).
  • Candlestick — encoding.open, high, low, close (optional volume).

Field types on channels are quantitative, temporal, ordinal, or nominal — never categorical (repairs to nominal as CK1007).

Layers that draw

Think in four layers. Later Concepts pages go deep on each.

  1. Identity — version, type, id, title, subtitle.
  2. Data & channels — data (rows, number array, or data.columns) + encoding (+ metric when needed).
  3. Marks & layout — mark (curve, sampling, stack, orientation, …), axes, size, legend.
  4. Chrome & runtime — theme, tooltip, annotations, interaction, animation, a11y. Some keys validate today but only draw with core/interact or warn CK3012 — see Bundles.

Richer example

Same line with mark, axes, theme, and size filled in. Defaults would look fine without them — this is explicit authoring.

json · with chrome 
{
  "version": "1",
  "type": "line",
  "title": "Weekly signups",
  "data": [
    { "week": "W1", "signups": 18 },
    { "week": "W2", "signups": 28 },
    { "week": "W3", "signups": 24 },
    { "week": "W4", "signups": 42 },
    { "week": "W5", "signups": 38 },
    { "week": "W6", "signups": 56 },
    { "week": "W7", "signups": 62 },
    { "week": "W8", "signups": 86 }
  ],
  "encoding": { "x": "week", "y": "signups" },
  "mark": { "curve": "monotone", "area": true, "sampling": "auto" },
  "axes": { "x": { "title": "Week" }, "y": { "title": "Signups", "grid": true } },
  "theme": "soft",
  "size": { "height": 280 },
  "legend": false,
  "a11y": { "alt": "Weekly signups rose from 18 to 86." }
}

What is not the type

  • mark is an options object (curve, sampling, …), not "line". A string mark is a CK1009 repair.
  • encoding.y.axis is "y" or "y2", not a title object — titles live under axes.y.title.
  • Aliases like type: "pie" → donut, "area" → stacked-area / mini-area, "point" → scatter (CK1005).
  • React component props are a separate API. Agents writing JSON should ignore JSX tables and use this schema.

Machine block

Rendered docs pages carry the live spec next to the SVG as <script type="application/json" data-ck-spec>. Option pages add id="ck-option". Prefer those blocks (and .md twins) over scraping prose.

For agents

Emit the object, then validate

Start from the minimal shape. Set type from the 14-core enum. Put measures in encoding or metric, never invent top-level value. Run validate() → repair() before render().
