MCP

mock-plausible Agents — @chartkitdev/mcp stdio server with a Flint-style few tools (not one per chart). Tools call @chartkitdev/core on the host; no network. Strategy names below; Soft = docs mock accent.

PACKAGE @chartkitdev/mcp · v0.5.0
TRANSPORT stdio · MCP SDK
STATUS install coming soon

Not on npm yet

Publish is gated · checkout works

npx @chartkitdev/mcp will not resolve until Todd publishes. From a repo checkout: npm run build --workspace=@chartkitdev/mcp then node packages/mcp/dist/cli.js. Point Cursor / Claude at that command. Do not write logs to stdout.

1 list / schema 2 validate → render 3 suggest / to_code

Six tools · Flint-style

Strategy surface: few tools that cover the whole catalog. Checkout today also exposes repair, lookup_feature, and get_example under shorter names (validate / render). This mock uses the strategy names for the try-it.

list_chart_types none checkout

Chart types from bundled examples, with filenames. Specs themselves come from get_schema / examples.

get_schema(type) type planned

JSON Schema fragment (or resource slice) for one chart type. Resource chartkit://schema/v1.json already ships the full v1 schema.

validate_chart spec ≈ validate

Core validate(): ok, diagnostics, errors, warnings, JSON Patch fix arrays. Spec is not mutated.

render_chart spec · format? ≈ render

Local SVG via @chartkitdev/core/extra (every type). No data leaves the host. PNG is not implemented (no native/wasm rasterizer).

suggest_chart data · goal planned

Pick a type from row shape + goal string; return a starter spec the agent can validate next.

to_code spec · framework planned

Emit React / Vue / Svelte / vanilla mount snippets for a valid spec. Adapters stay thin over core.

Bundled at build time — not fetched over the network.

chartkit://schema/v1.json v1 schema bundled
