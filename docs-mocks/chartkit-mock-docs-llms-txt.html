llms.txt

mock-plausible Agents — published LLM indexes: llms.txt (≤6400 B), llms-full.txt, and llms.json. Served from docs/public/ at extensionless prod URLs. Facts below match the repo on disk (core v0.5.0).

SOURCE docs/public/llms*.txt · llms.json
CAP llms.txt ≤ 6400 B
STATUS shipped

Three indexes

Agents get one of three files. The short index is the with-docs prompt in the agent eval. Full text adds field rules; JSON is structured for tooling.

/llms.txt 6,400 B · at cap index

Rules, repair loop pointers, Mermaid note, and one fenced JSON spec per chart type (27 types). Cap enforced in mermaid.test.ts.

/llms-full.txt 18,118 B reference

Longer rules (encoding repairs, Phase 4, combo, sampling), same drawable examples, plus choosing-a-library context from benchmarks.

/llms.json 8,552 B structured

$schema → llms-schema.json. Packages, exports, themes, hooks, resources.llmsTxt / llmsFullTxt / llmsJson.

For agents

Put llms.txt in the prompt

On the 2026-10-16 eval (claude-sonnet-4-5, 42 tasks, not re-run for round 13), ChartKit with llms.txt scored 42/42 first try at a mean of 131.1 output tokens. The old React-only file scored 18/42. Prefer the short index unless the model needs field-level repair rules from llms-full.txt.

What’s inside llms.txt

Header pins @chartkitdev/core v0.5.0 and schema/v1.json. Rules cover version, a11y.alt, row-shaped data, repair(), Phase 4, and Mermaid. Then one minimal valid spec per type:

docs-spec.test.ts parses every ```json fence in llms.txt, llms-full.txt, and packages/core/README.md, runs validate / validatePhase4, and asserts render() draws (no ck-chart-error).

Serving · discovery

Static files under docs/public/. Next config sets plain text / JSON headers and Cache-Control: public, max-age=86400. Layout exposes ai:llms / ai:llms-full and <link rel="alternate" type="text/plain">. /.well-known/llms.txt re-reads public/llms.txt (or redirects to prod).
